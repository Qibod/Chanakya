## Summary

The mapping engine itself is well‑factored: `computeIncrementalCoverage`, `parseFrameworkRefsArray`, `distinctFrameworkIdsFromRefs`, `isControlSharedAcrossFrameworks`, and `sharedControlsCountForFramework` are pure, tested, and shared between API and client via `@grc/types`. The activation route now returns `alreadyCoveredCount` + `frameworkLabel` + `coverageBreakdown`, the test asserts the canonical case (existing SOC2 → adding ISO27001 yields `alreadyCoveredCount: 3`), and several carry‑forward items from 2.4/2.5 reviews finally landed: `aria-pressed` on framework cards, audit‑log `toHaveBeenCalledWith` shape, the `ON CONFLICT` narrowing assertion, the `Red Sox` adversarial recommender test, the centralized `tenant-schema.ts` helper, and the `Number.MAX_SAFE_INTEGER`‑style `FRAMEWORK_IDS.length` cap.

That said, three issues block merge:

1. **`GET /v1/controls/:id` references undefined identifiers.** Lines 301–302 of `frameworks.ts` use `TENANT_SCHEMA_NAME_RE.test(schema)` and `invalidSchemaReply(reply)` — but neither is imported. The other four routes were migrated to the new `ensureTenantSchemaNameOrReply` helper; this one was missed. This will throw `ReferenceError` at runtime on every request. The test claims to pass — that means either the test's tenant schema happens to match the regex name and the throw is masked behind something, or the test never actually runs in CI. Either way, this needs to be fixed and verified end‑to‑end before merge.
2. **The activation toast blocks navigation for ~2.8 s.** `FrameworkSelectionClient.onSuccess` does `setCoverageNotice → await setTimeout(2800ms) → router.push("/onboarding/integrations")`. The mutation button stays "Activating…" the entire time, the toast itself is only visible while the user can't act on it, and after `router.push` the toast unmounts — so the user often *never* sees the message. AC #4 says **non‑blocking**.
3. **The detail SidePanel has no focus trap and no focus restoration.** Tab key escapes the dialog into background content (now obscured by the scrim button), and on close, focus is lost rather than returned to the row that opened the panel. AC #3 + 2.5's a11y bar set the expectation; this falls short.

A handful of smaller items follow.

**Verdict: Request Changes.** Issue #1 is a runtime crash; #2 is a real UX defect; #3 is the kind of a11y miss that compounds. After those, the rest is suggestions.

## What Looks Good

- **Pure types do the heavy lifting.** `parseFrameworkRefString`, `parseFrameworkRefsArray`, `distinctFrameworkIdsFromRefs`, `isControlSharedAcrossFrameworks`, `sharedControlsCountForFramework`, `computeIncrementalCoverage`, `formatNewFrameworksLabel` are small, named, deterministic, and tested. The shared `@grc/types` module continues to be the spine that keeps client and server honest.
- **`computeIncrementalCoverage` math is correct and tested.** Pre‑transaction read of existing `canonical_id`s, intersected with `CANONICAL_CONTROLS` filtered by each newly activated `frameworkId`. The `alreadyCoveredCount = 3` test (existing SOC2 + adding ISO27001) locks the contract using catalog data.
- **Carry‑forward fixes from 2.4/2.5 reviews shipped here:**
  - `aria-pressed` on framework toggle buttons (with the correct "undefined when disabled" idiom).
  - `prisma.platformAuditLog.create` argument matching in `frameworks.test.ts`.
  - `ON CONFLICT … DO UPDATE` narrowed to `framework_refs` only (test now asserts `not.toContain("name = EXCLUDED.name")`).
  - `Red Sox` adversarial recommender test guarding against bare `\bsox\b`.
  - `Number.MAX_SAFE_INTEGER`‑style "unlimited" for Scale collapsed to `FRAMEWORK_IDS.length`.
  - `tenant-schema.ts` helper extracted (and applied to four of the five routes — see Critical #1 for the miss).
  - `audit-ip.ts` helper used in both fingerprint and frameworks routes; activation test now exercises trustProxy + XFF.
- **Coverage breakdown is structured.** `coverageBreakdown: Record<FrameworkId, number>` is a clean shape for diagnostics, and the schema in `frameworks-api.ts` keeps it optional so older clients don't break.
- **Side panel structure is correct in spirit.** `role="dialog" aria-modal="true" aria-labelledby` + Escape handler + dim scrim button. The focus trap and restoration gaps (Critical #3) are the only thing standing between this and a clean a11y story.
- **Detail panel copy is honest.** "One evidence upload for this control satisfies every requirement listed above" — exactly what AC #5 asks for, framed in plain language without invoking the future Epic 4 evidence pipeline.
- **List page is appropriately minimal for 2.6.** Framework scope chips, badges per row, "Shared across frameworks" label, panel on row click. The story explicitly defers heavy list UX to Epic 3.1; the implementation honors that.
- **Detail endpoint contract is well typed.** `getControlByIdResponseSchema` includes `requirementDetails` parsed server‑side once, so the client doesn't re‑implement parsing.

## Verdict

**Request Changes.** Once the `GET /v1/controls/:id` reference error is fixed (and the test re‑run for real), the activation toast is moved to a non‑blocking sessionStorage handoff, and the panel gets a focus trap + focus restoration, this story is mergeable. The data model and pure functions are in good shape, and the carry‑forward backlog from 2.4/2.5 is finally moving in the right direction.

### Suggested follow‑ups (in order)

1. Replace `TENANT_SCHEMA_NAME_RE.test(schema)` / `invalidSchemaReply(reply)` in `GET /v1/controls/:id` with `if (!ensureTenantSchemaNameOrReply(reply, schema)) return;`. Re‑run `pnpm --filter @grc/api test` and confirm `frameworks.test.ts` actually passes.
2. Move the activation toast to a sessionStorage‑backed banner on `/onboarding/integrations` (peer to `IntegrationsOverlapBanner`); navigate immediately on success.
3. Add focus trap + focus‑on‑close restoration to `ControlLibraryClient`'s detail panel; capture `document.activeElement` on open.
4. Switch `ControlLibraryClient`'s list query to `useInfiniteQuery` + `nextCursor`; respect server‑side filtering when the route grows that capability.
5. Animate the panel slide (`translate-x-full → translate-x-0`) — currently the `transition-transform` class is a no‑op.
6. Subscribe to `(prefers-reduced-motion: reduce)` change in `ControlLibraryClient`'s `useEffect` (parity with fingerprint client).
7. Tighten audit semantics: either rename `framework.activated`'s `resourceId` to be the snapshot, or set it to just the new `frameworkIds` for clarity.
8. Add `tenant-schema.test.ts` covering the regex; tests for the detail panel a11y behaviors; deterministic `overlapPercent` value assertion in the growth test.
9. Land the carry‑forward items called out in #24 and #25 (2.4 / 2.5 review blockers).
