## Summary

Solid pass. Domain grouping with stable two‑level sort, collapsible sections, three filter axes (framework/status/owner) joined with AND logic, sessionStorage persistence for both filters and collapsed state, `StatusChip` + minimal initials avatar + relative/absolute "Last updated" per row, and a side panel that now actually animates (`translate-x-full → translate-x-0`, 200 ms, max‑width 400 px) — all wired through TanStack Query without spinner regressions. Several carry‑forwards from 2.6 landed cleanly: the `(prefers-reduced-motion)` matchMedia subscription is now a `change` listener (2.6 #6), the panel slide is no longer a no‑op (2.6 #5), and a hand‑rolled focus trap + `openerRef`-based focus restoration close the dialog a11y gap from 2.6 Critical #3. Tests cover the canonical shapes: domain collapse hides rows, framework + owner AND yields zero results, "Clear all" restores them, Escape closes the panel and returns focus to the trigger.

That said, three issues warrant changes before merge:

1. **`listControlsResponseSchema` in `@grc/types` was not updated.** The route now emits `assignedTo` and `updatedAt`, the UI consumes them, but the canonical Zod schema in `packages/types/src/frameworks-api.ts` still defines `items` as `{id, canonicalId, name, domain, status, framework, frameworkRefs}` only. The dev's File List omits this file entirely. Any future client that imports `ListControlsResponse` (or anyone running `safeParse` against the live response) silently loses the new fields. The UI escapes this because it uses an inline local type — that is the bug, not the workaround.
2. **Row a11y is incomplete against the story's own Task 3.** Each row's focusable element is a `<button aria-label="Open details for {name}">`. Status, assignee, and "Last updated" are wrapped in inner `<span>`s with their own `aria-label`/`title`, but those don't surface to screen reader users tabbing through rows — the button's accessible name is just the control name. Task 3 explicitly says "status not color-only; avatar has label; timestamp announced." That bar isn't met when the row is the focused thing.
3. **`PATCH /v1/controls/:id` ignores its parsed body.** `patchControlBodySchema.safeParse(...)` runs at line 387, but `parsed.data` is never read; the handler unconditionally sets `assigned_to = $1` to `request.user.userId`. Pre‑existing (looks like a 2.5 finalize‑dismiss hook bolted on to a stub PATCH), but it lives in the file 3.1 modifies and will silently mis‑handle assignment the moment any UI wires up an "Assign owner" affordance. Worth fixing now before this gets layered on.

A handful of smaller items follow.

**Verdict: Request Changes.** All three above are small fixes; the rest is suggestions and forward‑looking.

## What Looks Good

- **Stable two‑level sort.** `grouped` sorts domains alphabetically and rows by name within domain (line 229–243). Deterministic ordering means the collapse/expand UI doesn't shuffle on re‑render — important for keyboard navigation.
- **Filter pipeline is one `useMemo` with a clean AND chain** (line 203–218). Easy to read, easy to extend with future axes (BU, last‑updated range), and deps are exactly the three filter values plus the source data.
- **SessionStorage persistence is dual‑track.** Filters and collapsed domains have separate keys (`controlLibrary.filters`, `controlLibrary.collapsedDomains`) so wiping one doesn't disturb the other. The hydration effect swallows malformed JSON quietly. Story Task 4 ("persist filter state in‑session only") is satisfied.
- **`(prefers-reduced-motion)` is now a live subscription.** Lines 134–141 use `addEventListener('change', …)` with the optional‑chain pattern that survives older browsers — exactly what 2.6 review #6 asked for.
- **Panel slide actually animates.** `panelOpen` flips on the next `requestAnimationFrame` after mount, so the initial paint is `translate-x-full` and the next paint is `translate-x-0` — a real 200 ms ease‑out, not the previous CSS‑with‑no‑state‑change no‑op. Closes 2.6 #5.
- **Focus restoration is correct.** `openerRef.current = document.activeElement` on open, `openerRef.current?.focus?.()` on cleanup. The Escape‑close test asserts this end‑to‑end. Closes 2.6 Critical #3 in spirit (see #8 for the Radix recommendation).
- **API extension is minimal and surgical.** `assigned_to` and `updated_at` were already on `control_items` from the tenant template; the route just selects them and threads them through the response shape. No migration needed. The test locks `updatedAt` ISO formatting with `expect(...).toBe("2026-05-05T10:00:00.000Z")` — good.
- **Domain collapse semantics are correct.** `aria-expanded={!collapsed}` on the header button, `aria-controls` pointing at the region id, and the items list is conditionally rendered — not just `display: none`. Means assistive tech actually believes the rows are gone, which is the right semantic.
- **Empty state is differentiated.** `activated.length === 0` → "Activate a framework from onboarding to populate controls"; otherwise → "No controls in this view." Tells the user *why* the list is empty.
- **Tests cover the canonical interactions.** Domain collapse hides rows (not just toggles a class), AND filtering yields zero results when intersecting `unassigned + ISO27001`, "Clear all" restores both, Escape closes the dialog *and* returns focus to the trigger. The five test bodies are the ones the story would have asked for.

## Verdict

**Request Changes.** Three small, addressable items — schema drift in `@grc/types`, row a11y missing the story's own bar, and the latent PATCH bug — are blockers. Once those land, this is mergeable. The data flow, filter UX, and panel a11y story are otherwise in good shape, and the carry‑forward debt from 2.6 is mostly closed.

### Suggested follow‑ups (in order)

1. Update `listControlsResponseSchema` in `packages/types/src/frameworks-api.ts` to include `assignedTo: z.string().nullable()` and `updatedAt: z.string().nullable()`. Switch `ControlLibraryClient`'s local `ControlsListItem` to the inferred type. Confirm the test fixtures still typecheck.
2. Bring the row's accessible name up to the story bar — extend the button `aria-label` to a sentence form including status, owner, and last‑updated, or add an `aria-describedby` with a `sr-only` description that does the same.
3. Read `parsed.data` in `PATCH /v1/controls/:id`, validate the user id, return 401 instead of `""` coercion, and add the missing test suite for the endpoint (5 cases listed in #15).
4. Add `aria-pressed` (status) and `role="radio"`/`aria-checked` (framework, owner) to the filter chip groups; bring StatusChip filter labels into parity with the chip labels in rows.
5. Drop the StatusChip's per‑instance `role="status"` to a `sr-only` label (a11y fix that benefits every list view going forward).
6. Wire `useInfiniteQuery` against the existing `nextCursor`, or surface a "Showing first 500" banner when `total > items.length`. While editing the route, accept `?status=`/`?framework=`/`?assigned=` query params even if unused.
7. Replace the hand‑rolled focus trap with Radix `FocusScope`; soften the scrim from `bg-black/50` to a token closer to the spec's "subtle".
8. Add deterministic `Date.now()` stubbing to the "renders … last-updated metadata" test and assert a positive AND‑filter intersection in the filter test (one row, not zero).
9. Land the 2.4 / 2.5 carry‑forward items called out in #25.
