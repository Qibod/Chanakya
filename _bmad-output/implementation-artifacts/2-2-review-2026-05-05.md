## Summary

Solid first pass. The acceptance‑critical pieces are present and reasonably well‑structured: the SSE‑safe BFF proxy correctly branches on `text/event-stream` instead of buffering with `await upstream.json()`, the client uses `EventSource` over the same‑origin BFF (so the Clerk session cookie reaches `auth()`), and slice validation is performed at every JSON boundary with `@grc/types` Zod schemas. Phase mapping matches the story's normative table, and the synthetic Integrations line lets the four‑phase arc complete as required by AC #5. Reduced‑motion is handled in both React state and CSS.

That said, there are a handful of correctness, lifecycle, and test‑coverage issues that should land before this is merged. The two I'd block on are: (1) `EventSource.onerror` will trigger a polling fallback even after a successful completion, replaying the stagger animation; and (2) `submit()` does not tear down an in‑flight `EventSource`/poll, so a second submission can produce cross‑talk between job IDs. Several of the AC‑listed tests in Task 8 are also missing (reduced motion, override badge, failure path, sources popover), so the "all tests pass" claim is true but understates the gap.

**Verdict: Request Changes** — small surface, but a couple of real bugs and missing tests against ACs the story itself called out.

## Critical Issues

| # | File | Line(s) | Issue | Severity |

| 1 | `FingerprintOnboardingClient.tsx` | 199–202 | `es.onerror` unconditionally calls `startPolling(jobId)`. After `onCompleted` runs `es.close()`, browser quirks (network drop racing with completion) can still surface an `error` event, and the poll will then hit `GET /v1/fingerprint/:jobId`, find `pending_review` + inference, and call `handleInferencePayload(row.inference)` again — which resets `visibleCount` to 0 and **replays the stagger**. Track a `completedRef` (or `failedRef`) and bail out of `onerror` if either is set. | 🔴 Critical |
| 2 | `FingerprintOnboardingClient.tsx` | 215–251 | `submit()` doesn't close the previous `esRef.current` or call `stopPoll()` before starting a new request. Today the form is hidden once `lines.length > 0`, but during `error` / `failed_job` states the form re‑renders, and a stale poll started by a previous `onerror` can still be running. A successful new POST will overlay a second `EventSource`, and the old poll will continue against an old jobId. Defensively call `esRef.current?.close(); stopPoll();` at the top of `submit()`. | 🔴 Critical |
| 3 | Tests | n/a | Story Task 8 lists "reduced motion, stagger timing (mock timers), override saves badge" component tests and "failure event handling" coverage. The integration test only covers the happy path; reduced motion, stagger timing, override commit/badge, sources popover, and `fingerprint.failed` are not exercised. ## What Looks Good

- **SSE‑safe proxy:** content‑type branching is the right call; passing `upstream.body` straight into `NextResponse` avoids buffering, and the headers (`Content-Type`, `Cache-Control: no-cache`, `Connection: keep-alive`, `X-Accel-Buffering: no`) match the Fastify side.
- **Same‑origin auth pattern:** `EventSource` → BFF → Fastify lets Clerk's session cookie satisfy `auth()` server‑side, sidestepping the "`EventSource` can't send `Authorization`" pitfall.
- **Schema discipline:** every JSON boundary is parsed with `@grc/types` Zod schemas (`fingerprintInferencePayloadSchema`, `fingerprintJobEventSchema`); no duplicated shapes in `apps/web`.
- **Pure `buildFingerprintLines`:** isolating the flatten‑and‑label step from the React tree keeps the function trivially testable and the component focused on lifecycle.
- **Phase mapping matches the story's normative table** and synthesizes the Integrations line so AC #5 is reachable today.
- **Reduced motion is handled at two levels** (state short‑circuit + CSS), so even if one is bypassed (e.g. SSR hydration timing), the other still respects the user setting.
- **Manual‑setup stub is wired** so the failure path is never a dead end (AC #6).
- **Architecture compliance checklist items are met:** browser → BFF only, Tailwind tokens (mostly), tenant‑scoped jobId from server.

## Verdict

**Request Changes.** The two lifecycle bugs (#1 and #2) and the missing AC‑driven tests (#3, #21, #22) are merge‑blockers in my view. Everything else in the Suggestions table is high‑signal but landable as follow‑ups. A focused 1–2 hour pass covering the lifecycle fixes, a `completedRef`, eager teardown in `submit()`, and the four missing tests would put this in good shape.

### Suggested follow‑ups (small, scoped)
1. Add `completedRef`/`failedRef` and gate `es.onerror`.
2. Tear down `esRef` and `pollRef` at the top of `submit()`.
3. Pass `request.signal` into the BFF `fetch`.
4. Cap `startPolling` retries (with a meaningful timeout reason).
5. Replace custom tooltip/popover with Radix primitives (Tech Reqs).
6. Reset `edited[id]` when bulk‑edit reverts to default text.
7. Fix `PhaseProgressArc` aria conflict; switch to design tokens.
8. Add reduced‑motion / stagger‑order / override‑badge / failure / sources‑popover tests; keep Task 8 `[x]` honest.
9. (Cross‑story) revisit the SSE sanitization debt from 2.1 before production.
