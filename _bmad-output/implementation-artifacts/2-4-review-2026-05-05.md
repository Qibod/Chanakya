## Summary

The most ambitious of the three Epic 2 stories so far, and the data‑model decisions are the right ones: a `canonical_id`‑keyed `control_items` table with `framework_refs JSONB` for cross‑framework dedup, a tier‑aware `validateFrameworkSelectionCount` shared from `@grc/types`, transactional inserts behind `requireTier("starter") + requireRole("ControlOwner")`, and a clean separation between catalog metadata (typed) and tenant state (raw SQL into the tenant schema). The dashboard hook + `IntegrationsOverlapBanner` round out AC #6 reasonably without over‑investing ahead of Story 2.5's persistent checklist. The new `trustProxy` flag in `apps/api/src/server.ts` is also a welcome systemic fix.

Three things keep me from "approve":

1. **The audit‑log IP attribution issue from 2.3 was carried into this route verbatim.** `apps/api/src/routes/v1/frameworks.ts` reads `X-Forwarded-For` directly even though `server.ts` now sets `trustProxy: true` (so `request.ip` is finally trustworthy). With `trustProxy` enabled, `request.ip` is the right answer; reading the header by hand defeats the systemic fix, and any client behind the LB can spoof IP into the immutable `platform_audit_logs`.
2. **The legacy‑tenant migration script does not backfill `status = 'not_started'` → `'pending'`.** AC #2 explicitly says "do not leave rows at generic `not_started` if the epic/dashboard contract is `pending`." New tenants are fine (template DDL defaults to `pending`), but existing dev schemas with rows already at `not_started` will silently violate the contract.
3. **`ON CONFLICT (canonical_id) DO UPDATE`** rewrites `name`, `domain`, `framework`, and `control_code` on every re‑activation. That's defensible today (no user‑edit surface for those fields yet), but it's a footgun for Story 3.1+ where the user *can* edit `name`/`description` — re‑activating a framework would silently revert customizations. Either narrow the UPDATE clause to merge `framework_refs` only, or document the override semantics inline.

Verdict: **Request Changes**. All three are small fixes; the rest is good. Test coverage should also be deepened around the audit log shape, overlap percent, recommendations from a real committed fingerprint, and the `ON CONFLICT` re‑activation path.

## What Looks Good

- **Catalog → API → UI handoff is tight.** `@grc/types` is a single source for `FRAMEWORK_IDS`, library metadata, the merge function, the recommendation function, and the activation request/response Zod schemas. The route imports them all; the UI re‑declares the `FrameworkId` union locally only for typing convenience (acceptable). No drift surface.
- **Schema evolution is real, not ad‑hoc.** `tenant-template.sql` updated for new tenants, plus a separate per‑tenant migration script for legacy schemas (with `IF NOT EXISTS` guards). The integration test in `tenant-isolation.test.ts` was also updated to insert the new shape — that's the right discipline.
- **Tier policy is in `@grc/types`, not the route.** `validateFrameworkSelectionCount` and `maxFrameworkSelectionsForTier` are pure functions with their own tests; the route just consumes them. This is the pattern we want.
- **`trustProxy` was wired up systemically in `server.ts`.** That's the right answer to the audit‑IP class of issue from 2.3 — the **route** just needs to use `request.ip` to take advantage of it.
- **Onboarding flow is wired end‑to‑end.** Fingerprint confirm → frameworks → integrations → dashboard, with sessionStorage flags driving the checklist, and TanStack Query invalidation on activation so the dashboard's `controls-list` query refreshes when the user lands.
- **Cross‑framework dedup is correct.** `mergeCanonicalControlsForFrameworks` deterministically computes refs sorted, includes only canonical controls that map to ≥1 selected framework, and `computeOverlapPercent` matches the AC formula precisely.
- **Soft upgrade prompt for Starter** matches the PRD "conversion without sales call" intent — no hard paywall, no navigation block, just a dismissible inline message.
- **`ON CONFLICT (canonical_id) DO UPDATE` for control_items is correct in shape** (preserves `status`, `assigned_to`, `business_unit_id`, `description`) — the issue I flag in #3 is forward‑looking, not a current bug.

## Verdict

**Request Changes.** Three small fixes (use `request.ip`, backfill legacy `not_started` → `pending`, narrow the `ON CONFLICT … DO UPDATE` clause) plus a real round of test depth on audit‑shape, overlap‑percent, recommendations, and `ON CONFLICT` re‑activation. The architecture and contract decisions are sound and consistent with 2.1–2.3.

### Suggested follow‑ups (in order)

1. Replace raw‑XFF IP parsing with `request.ip` in `frameworks.ts` (and `fingerprint.ts`); extract a tiny `auditIp(request)` helper to keep both routes consistent.
2. Add `UPDATE … SET status = 'pending' WHERE status = 'not_started'` to the per‑tenant migration script.
3. Narrow `ON CONFLICT (canonical_id) DO UPDATE` to merge `framework_refs` (and `updated_at`) only; comment why.
4. Map Postgres unique‑violation (`23505`) on `framework_activations` to `409 FRAMEWORK_ALREADY_ACTIVE`.
5. Replace `99` in `maxFrameworkSelectionsForTier` with `FRAMEWORK_IDS.length` (or `Number.MAX_SAFE_INTEGER`).
6. Add a GIN index on `control_items.framework_refs`.
7. Replace `data::text != '{}'` with `data <> '{}'::jsonb`; parallelize the two GET queries.
8. Tests:
   - Audit log `toHaveBeenCalledWith` shape.
   - Overlap percent in activation response.
   - `ON CONFLICT` re‑activation path (verify merged refs + preserved status).
   - Recommendations from a committed fingerprint row vs. empty fallback.
   - `controls-list` returns rows with multi‑element `frameworkRefs`.
   - Adversarial recommendation regex inputs ("Red Sox", "queue").
   - Tenant‑isolation for `framework_activations`.
9. Clear `grc_onboarding_overlap_percent` in `FingerprintOnboardingClient.submit()` so re‑runs don't show stale banner.
10. UI: `aria-pressed` on framework cards; switch dashboard page raw `slate-*` to design tokens; pre‑flight that `(onboarding)/layout.tsx` provides a `QueryClientProvider`.
