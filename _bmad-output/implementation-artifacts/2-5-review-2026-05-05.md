## Summary

This is the strongest of the four Epic 2 stories I've reviewed. The derivation model is the right one — five flags computed from authoritative tenant DB rows (`fingerprint_results.committed`, `framework_activations`, `integration_configs.connected`, `control_items.assigned_to`, `tenants.onboarding_first_report_completed_at`) instead of fragile sessionStorage — and the surface area is well partitioned: a tiny pure types module, a single derivation service, a thin route layer, and three small client components (Checklist, Banner, StepHelp). It also lands a substantial chunk of the carry‑forward backlog from earlier reviews:

- **2.3:** `409 ALREADY_COMMITTED` is now treated as a successful navigation, with a test.
- **2.4:** `auditIpFromRequest` helper extracted (with its own test) and applied to both `fingerprint.ts` and `frameworks.ts`; `ON CONFLICT (canonical_id)` narrowed to `framework_refs` only; Postgres `23505`/Prisma `P2002` mapped to 409; `data <> '{}'::jsonb`; cursor pagination on `/v1/controls`; tenant‑schema regex guard added to onboarding + PATCH controls; dashboard moved off raw `slate-*` to design tokens.

That said, three items keep me from "approve":

1. **The actual derivation service is untested.** `computeOnboardingSteps` and `finalizeDismissIfComplete` are mocked out of the route test. The five‑step truth function is the heart of this story and has zero coverage today.
2. **`OnboardingBanner` does not honor `dismissedAt`.** It hides only on `allComplete`. AC #5 says "dismissed permanently for that tenant"; if any step regresses after auto‑dismiss (e.g. a control's `assigned_to` is unset), the banner re‑appears even though the tenant has explicitly completed onboarding. The checklist correctly checks `dismissedAt`; the banner doesn't.
3. **`JARGON_BANNED_SUBSTRINGS` only has three entries** and the test trivially passes. AC #4 explicitly bans "control codes like CC6.1, Annex A, ISO clause IDs, etc." Use a regex pattern (or a fuller list) so a future copy edit can't sneak `Art.32` / `ITGC‑404` / `A.12.1` past the guard.

Verdict: **Request Changes.** All three are small, and the rest of the story is high‑quality.

## What Looks Good

- **Server‑backed truth.** Five flags computed from authoritative tenant rows in a single `Promise.all`, with `tenants.onboarding_first_report_completed_at` as the only explicit‑completion column needed (because Epic 5 reports don't exist yet). Honest design — no phantom rows, no derived booleans masquerading as data.
- **Type discipline.** `ONBOARDING_STEP_IDS`, `OnboardingProgressData`, `postOnboardingCompleteStepBodySchema`, `patchControlBodySchema` are co‑located in one tiny module, exported from `@grc/types`, and consumed by both the API and the web client without local re‑declarations.
- **Carry‑forward is real.** Almost every actionable item from the 2.3 and 2.4 reviews shipped here: `409 ALREADY_COMMITTED` → success on the client (with a test), `auditIpFromRequest` helper extracted (with its own test), `ON CONFLICT` narrowed, `23505/P2002` → 409, `data <> '{}'::jsonb`, cursor pagination on `/v1/controls`, schema regex guard on the routes that got touched, dashboard moved off raw `slate-*`, fingerprint client invalidates `["onboarding-progress"]` after confirm, FrameworkSelectionClient invalidates the same key.
- **Single source of truth for the checklist.** The inline `<aside>` in `FrameworkSelectionClient` is gone; `OnboardingChecklist` is mounted once per layout and consumed by all onboarding pages. `DashboardOnboardingActions` shows the residual CTAs only for steps that aren't done yet.
- **Auto‑dismiss is correct.** `finalizeDismissIfComplete` is called from both `complete-step` and `PATCH controls/:id`, uses `COALESCE` so re‑entries don't move the timestamp, and only writes when `allComplete` — clean idempotent behavior.
- **Help copy is plain‑English.** No control codes in any of the five entries. Banned‑substring test is too thin (Critical #3) but the copy is genuinely jargon‑free, and the structure is right (`title`, `body`, `whyItMatters`).
- **Help widget keyboard support.** Escape closes, focus moves into the panel on open, click‑outside dismisses. (Two refinements suggested above.)
- **Layout integration.** `(onboarding)/layout.tsx` wraps children with the checklist column on the right; `(app)/layout.tsx` adds the banner above `<main>`. `Providers` already wraps the app with `QueryClientProvider`, so the 2.4 review pre‑flight is satisfied.
- **DDL changes are minimal and reversible.** `tenants` gains `onboarding_dismissed_at` + `onboarding_first_report_completed_at`; the per‑tenant migration script is `IF NOT EXISTS`‑guarded.

## Verdict

**Request Changes.** The three critical items are small and self‑contained. The architecture and contracts are clean and consistent with 2.1–2.4; the carry‑forward fixes are evidence the team is listening to review feedback. After fixing the banner's `dismissedAt` gate, beefing up the jargon regex, and adding direct tests for `computeOnboardingSteps` / `finalizeDismissIfComplete`, this is mergeable.
